## 0. 요약
- 목표: 기종을 알고 있는 이미지에 대해 스텝마다 PASS/FAIL과 일치율을 낸다(`구분번호:일치율:결과`, 예 `C550:90:OK`). FAIL이 극소하다.
- 1차 접근(전체 이미지 이상탐지·ROI)은 실제 FAIL 11건 중 1–2건만 검출했고, 불량 사진에도 라벨이 있어서 "있다/없다"가 아니라 "맞는 라벨인가"를 봐야 한다는 것이 핵심 문제였다.
- 전환: (1) 엑셀 확인 포인트표로 정상 파일의 정답(기종x스텝의 기대 부품·라벨)을 자동으로 만든다. (2) 고정 좌표 대신 사진 속 기준점(앵커)을 찾아 라벨 위치를 직접 잡는다. (3) 기준 라벨과 비교해 판정한다. (4) 위치를 못 찾으면 FAIL이 아니라 "재확인 필요"로 둔다.
- NG 폴더는 정답이 아니다. 공정에서 NG로 표시한 사진일 뿐이어서 촬영 오류·재촬영 사유일 수 있다. 정상·NG 폴더를 같은 기준으로 판정하고 NG 폴더 결과는 참고로 비교한다.
- 앵커 기반 방식(스텝 1·2·3·7)과 부품 탐지기(스텝 6, 8–14, 5.6c)를 적용한 뒤 NG 폴더 사진 12장을 사람이 직접 확인했다. 부품·라벨 불량이나 오촬영으로 확인된 7장(스텝 1·2·3×3·7·9)은 모두 자동 검출했고, 정상(흐림·어두움·각도 차이·문제 없음)으로 확인된 5장(스텝 6·8·9·14×2)은 모두 OK로 판정했다. 오탐·미탐은 이 12장에서 0건이다(소규모이고 방법을 만드는 과정에서 본 사진이라 낙관적일 수 있다). 정상 3,214제품 전체에서 한 스텝이라도 이상인 제품은 71대(2.2%)이다. 학습에 쓰지 않은 시험 세트 671제품에서는 37대(5.5%)가 한 스텝이라도 이상으로 판정되었다(6절). 이 값은 학습에 쓴 사진으로 잰 2.2%보다 높으며, 새 사진에서의 기대치는 후자가 아니라 전자이다.

## 0-1. 전체 흐름: 무엇을 보았고, 그래서 무엇을 했고, 왜 그랬는가
각 단계는 [관찰 -> 결정 -> 근거] 순서이며, 괄호의 숫자는 근거가 되는 절이다.

1. **데이터를 확인했더니 불량이 거의 없었다.** 3,214제품 중 FAIL 제품은 9개(0.28%)이고 FAIL이 있는 기종은 3개뿐이었다. 사진은 모두 1024x768이지만 손으로 든 카메라라 이동과 회전이 크다(2절).
   - 결정: 불량을 보고 배우는 지도학습은 학습도 검증도 불가능하다. 정상 사진만으로 기준을 만들고 그 기준에서 벗어나면 NG로 보는 이상탐지로 간다. GPU가 없으므로 신경망 없이 CPU로 계산하는 특징과 거리 계산을 쓴다(1절, 5.7절).

2. **전체 사진을 비교하는 첫 방식은 실제 불량을 거의 못 잡았다.** 정상 사진과의 전체 이미지 이상탐지를 시험하자 실제 FAIL 11건 중 1–2건만 검출됐다. 검출 영역을 라벨 부분으로 좁히면 "라벨 없음"은 분리됐지만, 글자가 빠졌거나 2206N 대신 2006N이 붙은 경우는 분리되지 않았다(3절, 부록 A).
   - 관찰: 불량 사진에도 라벨은 붙어 있다. 필요한 질문은 "라벨이 있는가"가 아니라 "이 기종, 이 스텝에 맞는 라벨인가"이다. 또 카메라가 손으로 움직여 고정 좌표나 전체 정렬은 사진마다 어긋난다. 정렬을 성공시켜도 점수 분포가 바뀌지 않았다(부록 A 5.5).
   - 결정: 정렬 대신 사진 속 기준점(앵커)을 찾아 비교할 부분을 직접 잘라 내고, "맞는 라벨인가"를 기종별 기대값과 비교한다. 기준점을 못 찾으면 불량이 아니라 재확인으로 둔다.

3. **"맞는 라벨"의 정답을 만들어야 했다.** 엑셀의 확인 포인트표에서 기종x스텝의 기대 부품과 라벨을 가져와, 정상 폴더 사진을 그 기대값으로 자동 라벨링했다. 사람이 일일이 라벨링하지 않은 대신, 정상 폴더에 숨은 불량이 있으면 기준이 오염된다는 한계를 안고 간다(4절).

4. **NG 폴더를 정답으로 쓸 수 없었다.** NG 폴더는 공정에서 한 번 걸러진 사진이다. 사진 12장을 직접 보니 5장은 정상이거나 흐림, 어두움, 각도 차이일 뿐이었고, 부품·라벨 불량이나 오촬영으로 확인된 것은 7장이었다(5.5절).
   - 결정: NG 폴더는 학습에 쓰지 않고, 판정 뒤에 결과를 사례별로 대조하는 사후 확인용으로만 쓴다. 검출률을 이 폴더로 말하지 않는다(4절, 5.6c의 한계).

5. **기준점을 찾을 수 있는 스텝부터 스텝별로 설계했다.** 스텝 1·2·3은 부품 하나를 기준으로 잘라 비교하고, 스텝 4·5·7은 파란 부품의 면적을 봤다(5.1–5.4절).
   - 스텝 1: 두 라벨이 모양은 같고 문구만 달라 기대하는 쪽과 더 닮았는지를 본다.
   - 스텝 2: 각인은 모양이 고정이라 기준 모양과의 어긋남을 본다. 처음에는 951장 중 946장만 위치를 찾았지만 분할 임계를 순차적으로 시도해 3,214장 모두 찾았다.
   - 스텝 3: 가장 어려웠다. 시도를 9번 반복하며 위치 확인을 573/951에서 3,213/3,214로, 오탐을 31.8%에서 0으로 줄였다. 매 시도의 원인을 사진으로 확인하고 고쳤다(5.3절의 표).
   - 스텝 4·5·7: NG 폴더의 빈 트레이 사진에 파란 부품이 아예 없었고 정상은 화면의 약 26%여서 면적으로 구분된다.

6. **나머지 스텝은 장면 전체의 구성 비교로 시작했다.** 같은 기종 정상 중 가장 가까운 사진과의 거리를 잰다. 부품이 빠졌거나 엉뚱한 곳을 찍은 경우를 잡는 가장 단순한 장치이다(5.6절). 스텝 9의 USB/LAN 쪽을 찍은 오촬영이 이 방식으로 검출됐다.
   - 한계: 임계를 정상의 상위 0.5%로 정했으므로 정상 이상 비율이 낮게 나오는 것은 정의의 결과이다. 작은 부품 하나의 유무는 장면 전체 거리에 묻혀서 보이지 않는다.

7. **작은 부품을 보기 위해 부품 단위 비교를 시도했고, 두 방법은 실패했다.** 조각 비교와 정렬 후 잔차를 시험했지만 합성한 불량이 정상 범위 안에 들어갔다. 카메라는 지그에 고정이지만 제품이 놓인 위치와 각도가 달라, 정렬 기준이 마땅치 않았다(5.6b절).
   - 결정: 이 두 방법은 채택하지 않았다. 실패한 결과와 원인을 보고서에 남긴다.

8. **부품 하나를 직접 찾는 탐지기로 방향을 바꿨다.** 부품 위치가 사진마다 ±10% 달라 고정 위치를 보지 않고 사진 전체를 훑어 가장 닮은 곳의 점수를 쓴다. 대표 사진에서 부품 상자를 정하고, 정상 사진에서 그 상자와 닮은 곳을 찾아 양성 예시로 쓰되(판정에는 쓰지 않음), 이후 분류기를 직접 학습한다(5.6c절).
   - 같은 기종 사진이 적으면 "재확인"이 정상의 2% 가까이 쌓였다. 전체 기종 공통 탐지기로 대신하자 스텝 8은 68장에서 11장, 스텝 9는 48장에서 3장으로 줄었다.

9. **지금까지의 수치는 낙관적일 수 있어서 학습에 쓰지 않은 사진으로 다시 쟀다.** 판독기를 학습, 저장, 판독으로 나누고, 제품마다 사진 내용의 crc32로 20%를 시험 세트로 떼었다(이름은 쓰지 않음). 이 671제품의 결과로 한 스텝이라도 이상인 제품이 5.5%임을 확인했다. 학습에 쓴 사진으로 잰 2.2%는 새 사진의 기대치가 아니다(6절).
   - 이 평가에서 스텝 2의 오탐률이 앞서 보고한 0.3%가 아니라 1.3%임을 확인하고 정정했다. 분모에서 위치 게이트에 걸린 사진을 뺐던 것이 원인이었다.
   - 부품 탐지기의 임계 보정은 시험했지만 NG가 25장에서 42장으로 늘어서 되돌렸다.

10. **남은 한계를 숨기지 않고 적었다.** 정상 사진에 대한 오탐의 원인은 그림자, 화면 끝에서 잘린 부품, 다른 구도이며 부품이 빠진 것이 아니었다. 실제 불량 검출률은 NG 폴더가 정답이 아니어서 말할 수 없다. 임계값은 근거가 약한 초기값이고, 스텝 1에는 둘 다 아닌 라벨을 거르는 절대 기준이 없다(5.0절, 5.7절, 6.5절).

## 1. 문제 이해와 제약
| 요건 | 대응 |
|---|---|
| 기종별 이미지 -> 스텝마다 PASS/FAIL, threshold | 스텝별 모델 + 스텝별 기준선, 출력은 PASS(일치율) |
| FAIL 극소 | 정상만으로 학습하는 이상탐지 |
| GPU 없음 | 신경망 없이 CPU 연산(특징 추출 + 거리 계산) |
| 기성 알고리즘 결과를 판정에 그대로 쓰지 않음 | 점수·기준선 직접 구성. ORB/RANSAC·ECC는 카메라 위치 보정(전처리)에만 사용 |

## 3. 1차 접근의 한계와 문제 재정의
- 문제: 전체 이미지 이상탐지(부록 A)에서 실제 FAIL 11건 중 기준선으로 검출된 건 1–2건이었다. ROI를 라벨 영역으로 좁히면 "라벨 없음"은 분리되었지만 글자 누락·라벨 숫자 불일치(2206N 기대, 2006N 확인)는 분리되지 않았다.
- 관찰 1: 불량 사진도 라벨은 붙어 있다. 필요한 것은 "라벨이 있는가"가 아니라 "이 기종·이 스텝에 맞는 라벨인가"이다.
- 관찰 2: 고정 좌표 ROI는 핸디 카메라(회전 약 180도 포함, 이동·원근 변화) 때문에 사진마다 어긋난다. 전체 정렬(ORB·ECC)이 성공해도 점수 분포가 바뀌지 않았고(부록 A 5.5), 실패하면 판정 자체가 무의미해진다.
- 결정: (a) 기종x스텝의 기대 라벨을 엑셀 확인 포인트표에서 가져와 정상 파일을 자동 라벨링하고, (b) 정렬 대신 사진 속 기준점(앵커)을 찾아 라벨 위치를 직접 잡고, (c) 위치를 못 찾으면 FAIL이 아닌 "재확인 필요"로 둔다.

## 4. 자동 라벨링과 NG 폴더의 위치
- 엑셀 "화상검사Point" 시트의 확인 포인트(①~⑭)를 스텝별 기대 부품으로 옮겼다: ① 토너 지역 라벨(C550/C551), ② 좌전카바 각인 B793, ③ 제품명 라벨(2206N 등)·우전카바 인쇄 6323, ④ 현상 가압 조작 라벨 3102·레버 피스 3699, ⑤⑦ 적재 한도 라벨 1525, ⑥ 위치 결정 코마 2917, ⑧ 사이드 규제 잠금 라벨 8588(3029C010AA만)·모듈러 카바 0000, ⑨ 적재 한도 라벨 2899·위치 결정 블록 4357(3029C010AA만)·전원 스위치 3780, ⑩⑪ 카바 라이트 단조 V243/V242/B792, ⑫~⑭ 압판 스토퍼 3779·C160 원고 적재 제한 라벨(ADF 기종).
- 기종x스텝의 기대 라벨은 기종 고정(예: 제품명 라벨은 3029C003/005/006/009AA = 2206N, 004AA = 2206iF, 010AA = 2206i, 3030C001/002/003AA = 2206, 3030C004AA = 2206L, 3031C001/002/003AA = 2006N, C551은 3029C003/004AA와 3030C001AA). 정상 폴더 사진은 모두 기대 라벨이 붙어 있다고 보고 자동 라벨링했다. 사람이 직접 라벨링하지 않았고, 정상 폴더에 숨은 불량이 있으면 라벨이 오염되므로 `[TODO]` 이상 판정 사진을 눈으로 확인해 정리한다.
- NG 폴더 사진(`<제품>/NG/날짜_..._step_N.jpg`)은 정답으로 쓰지 않는다. 공정에서 NG로 표시한 사진일 뿐이라 촬영 오류·재촬영 사유일 수 있기 때문이다. 정상과 같은 기준으로 판정하고, 판정 결과와 공정 NG 표시의 일치 여부를 사례별로 적는다.
- 학습·평가: 제품 시리얼 단위로 60/20/20으로 분할(같은 제품의 사진이 학습과 시험에 나뉘지 않게), 기준선은 검증 정상의 1퍼센타일(또는 99퍼센타일). 일치율은 기준선에서 50이 되도록 변환.

### 5.6b 스텝 6, 8–15 부품 단위 비교 시도: 조각 비교와 정렬 잔차 (감도 부족으로 채택하지 않음)
- 동기: 5.6의 장면 거리는 나사 하나·포트 하나 같은 작은 변화를 희석한다. 사진을 보니 부품 위치가 ±10% 정도 사진마다 달라(손으로 들고 찍음) 한 곳을 고정해서 보는 방식은 맞지 않았다.
- 시도 1(조각 비교, `step_patch.py`): 사진을 32x32 조각 165개로 나누어 밝기 모양·방향 히스토그램·색 특징을 만들고, 같은 기종 정상의 조각들과 최근접 거리를 잰다(PatchCore를 CPU용으로 줄인 것). 점수는 큰 조각 3개 평균, 임계는 정상 99.5 백분위 x 1.5.

- 원인 해석: 조각이 지역 특징만 보기 때문에 나사가 없는 자리의 평평한 조각이 같은 사진의 다른 평평한 판 조각과 같아 보인다. 위치 가중치를 올리면 제품이 놓인 위치·각도 차이가 정상 점수를 같이 키워서 구분이 나아지지 않았다.
- 시도 2(정렬 후 잔차): 가까운 정상 5장에 이동 정렬(위상 상관)과 아핀 정렬(ECC)을 한 뒤 테두리 맵의 잔차를 구했다. 합성 불량의 점수는 정상 최댓값의 0.08–0.35배로 정상 중앙값(0.32배 수준)에도 못 미쳤다. 조명·원근 차이로 생기는 정상 잔차가 작은 부품의 변화보다 컸다.

### 5.6c 스텝 6, 8–14 부품 탐지기
- 동기: 5.6b의 조각 비교·정렬 잔차는 감도가 부족했고, 장면 거리는 작은 부품 하나의 유무를 못 본다. 그래서 부품 하나를 직접 찾는 분류기를 스텝마다 만들었다(스텝 15는 사진이 45장이라 설정을 만들지 않았다).
- 방법: (1) 대표 사진 한 장에서 부품 상자(스텝마다 한 개)를 사람이 정한다. (2) 정상 사진에서 그 상자와 가장 닮은 위치를 정규화 상관(NCC 0.55 이상)으로 찾아 양성 예시의 *시드*로만 쓴다(판정에는 쓰지 않는다). (3) 사진을 256x192로 줄여 직접 구현한 HOG 계열 특징으로 모든 창을 만들고, 양성 주변 창과 먼 창을 로지스틱 회귀로 학습한다. 가장 헷갈린 음성을 추가해 다시 학습한다(어려운 음성 마이닝). (4) 판정 점수 = 사진 전체 창 중 최댓값(부품이 어디 있든 찾는다). (5) 정상은 두 쪽(파일 내용의 crc32로 나눔, 이름은 쓰지 않음)으로 나눠 반대쪽 모델로 채점하는 교차 적합이고, 임계 = 정상 1퍼센타일 - 0.5 x (중앙값 - 1퍼센타일). 일치율은 점수에 대한 시그모이드(임계에서 50).
- 같은 기종 사진이 적어 단독 학습을 못 하는 경우(양성 후보 4장 미만)에는 처음에는 "재확인"으로 두었더니 스텝 8·9·14에서 정상의 2% 안팎(48–69장)이 이상으로 쌓였다(실제 부품 문제가 아니라 판정 불가였다). 전체 기종 공통 탐지기로 대신 판정하도록 고치자 스텝 8은 68→11장, 스텝 9는 48→3장, 스텝 14는 52→7장이 되었다. 화면 가장자리에 걸린 부품(스텝 11)은 창이 잘려 양성 표본이 0개가 되어 학습이 실패했는데, 가장 가까운 창으로 대신해 해결했다.

### 5.7 방법 선택의 근거와 근거가 없는 부분
이 절은 각 선택이 무엇에 기대는지를 구분해 적는다. 문헌에 근거한 선택, 이 데이터에서 직접 실험해 정한 선택, 근거 없이 정한 초기값을 섞어 쓰지 않기 위해서다.

| 선택 | 근거 | 근거의 한계 |
|---|---|---|
| 정상 사진만으로 기준을 만들고 벗어나는 정도로 판정 | 불량이 드물고 종류를 열거할 수 없을 때 정상 모델을 쓰는 접근이 이상탐지 문헌의 표준 설정이다(Chandola et al., 2009). 산업 이상탐지 벤치마크도 정상만으로 학습하는 설정을 쓴다(Bergmann et al., 2019). 이 데이터에서는 3,214제품 중 FAIL 제품이 9개(0.28%)라 지도학습이 불가능했다(2절). | 문헌은 이 접근이 일반적이라는 것까지만 보여준다. 이 공정의 사진에서 잘 작동한다는 근거는 아니며, 그것은 1차 접근의 실패(부록 A)와 이후 시험 세트 평가로만 확인했다. |
| 스텝 3 라벨 분류와 부품 탐지기의 특징(기울기 방향 히스토그램, HOG 계열)과 선형 분류기 | 기울기 방향 히스토그램에 선형 분류기를 얹는 구성은 물체 탐지의 대표적 방법이다(Dalal & Triggs, 2005). GPU 없이 CPU로 돌릴 수 있고 신경망보다 학습 사진이 적어도 된다. | 직접 구현한 단순화 버전이라 원 논문의 블록 정규화 등과 같지 않다. 다른 특징과 비교하지 않았다(HOG가 최선이라는 근거는 없다). |
| 부품 탐지기의 어려운 음성 추가 학습 | 가장 헷갈리는 음성을 모아 다시 학습하는 방식은 슬라이딩 윈도우 탐지기에서 쓰이는 방법이다(Felzenszwalb et al., 2010). | 이 데이터에서 어려운 음성을 넣은 경우와 넣지 않은 경우를 비교한 실험은 하지 않았다. |
| 교차 적합(정상을 두 쪽으로 나눠 반대쪽 모델로 채점) | 학습한 사진을 같은 모델로 채점하면 점수가 낙관적으로 나온다는 교차검증의 일반 원리. 이 데이터에서는 6.4절에서 보정 방식과 비교해, 보정이 NG를 25장에서 42장으로 늘린 결과로 교차 적합을 택했다. | 6.4의 비교는 부품 탐지기 스텝에만 했다. |
| 정상 점수 분포의 백분위로 임계 정하기(1·99·99.5퍼센타일, 여유 배수 1.5, 부품 탐지기의 0.5 x 간격) | 근거 없음. 정상 분포의 꼬리를 기준으로 삼는다는 생각 자체는 이상탐지에서 흔하지만, 위 수치는 정상 점수 분포와 육안 확인한 사진을 보고 정한 초기값이다. | 값을 바꿀 때 오탐률이 얼마나 변하는지의 민감도 분석을 하지 않았다. 시험 세트의 오탐률은 이 값이 합리적인 범위에 있다는 간접 증거일 뿐이며, 최적이라는 근거가 아니다. |
| 일치율 식(50은 임계, 감쇠는 0.5의 거듭제곱 또는 시그모이드) | 근거 없음. 임계에서 50이 되도록 점수를 0–100으로 바꾸는 표시용 변환이다. 단조 변환이라 PASS/FAIL 판정은 임계값이 결정하고 일치율 식은 판정을 바꾸지 않는다. | 일치율의 절대 크기(예: 90)가 확률이나 신뢰도를 뜻하지 않는다. |
| 파란 부품: HSV 색 범위와 면적 비율 | 색 공간 분할은 일반적인 방법이지만 이 범위(색상 95–135, 채도 하한)는 정상 사진을 관찰해 정했다. | 조명이 크게 다른 사진에서의 안정성은 시험하지 않았다. |

문헌 근거가 있는 항목도 "이 방법이 일반적으로 쓰인다"는 근거일 뿐 "이 문제에서 최선"이라는 근거는 아니다. 이 문제에서의 타당성은 시험 세트 평가(6절)와 단계별 실험으로만 판단하며, 비교 실험이 없는 항목은 한계로 남긴다.

## 6. 판독기 구조와 시험 세트 평가

### 6.1 구조: 학습, 저장, 판독의 분리
- 문제: 지금까지의 코드는 가진 사진으로 기준을 만들고 같은 사진을 채점하는 일괄 처리였다. 새 사진 한 장을 넣어 판정하는 형태가 아니었고, 학습에 쓴 사진으로 성능을 재면 낙관적이다.
- 결정: 세 부분으로 나눴다. (1) `train_all.py`가 스텝 1–15의 모델을 학습해 `model.pkl`로 저장한다. (2) `inspect_image.py`가 저장된 모델과 기종, 스텝 번호, 사진을 받아 `구분번호:일치율:결과`와 PPT 한 줄(`STEP 1 PASS(90.5) | STEP 2 FAIL(31.7) | ...`)을 출력한다. (3) `evaluate_holdout.py`가 학습에 쓰지 않은 사진을 판독해 스텝별 표와 이상 사유 분류를 만든다. 기종과 스텝 번호는 입력 정보이고, 파일·제품 이름은 판정에 쓰지 않는다.
- 판정 규칙: 한 스텝 안에서 하나라도 NG이면 NG, 아니면 하나라도 재확인이면 재확인이며, 일치율은 최솟값이다. 스텝 4·5는 파란 부품 면적과 장면 거리, 6·8–14는 장면 거리와 부품 탐지기, 7은 파란 부품 면적, 15는 장면 거리만 쓴다.

### 6.2 시험 세트: 이름을 쓰지 않는 분할
- 제품마다 가장 앞 스텝 사진 파일의 바이트로 crc32를 계산해 5로 나눈 나머지가 0이면 시험 제품으로 뗀다(3,214대 중 671대, 약 20%). 파일·제품 이름은 분할에 쓰지 않는다. 시험 제품의 사진은 학습, 임계값 정하기, 교차 적합에 모두 쓰지 않았다. NG 폴더 사진도 학습에 쓰지 않았다.
- 로고 임계값(스텝 2)만 별도로 crc32 나머지 1인 사진을 보정용으로 떼어 정했다.

## 부록 A. 1차 접근(전체 이미지 이상탐지)의 기록 (v2 본문)

### A3. 접근 선택: 정상만으로 학습하는 이상탐지
스텝당 FAIL이 1–3건이라 지도학습은 학습·검증 모두 불가능하고 불량 종류도 열거할 수 없다. 정상은 스텝당 수백 장이므로 "정상 분포에서 얼마나 벗어났는가"를 점수화하고 정상 검증셋의 퍼센타일을 기준선으로 삼는다.

### A4. 방법
1. 정렬(전처리): ORB 특징점 + RANSAC. 이중 게이트(inlier 수·비율, 변환량 상식 범위) 불통과 시 원본으로 진행(soft).
2. 특징: 32px 패치(256x192 기준 11x15 격자) x 20차원 = 엣지 방향 8(크기 가중·L1 정규화) + 채도 가중 Hue 8 + 평균 채도·텍스처 4. 옵션: gray-world 색 보정.
3. 모델(patch-kNN): 격자 위치마다 학습 정상의 같은 위치 +-1칸 이웃 패치로 뱅크를 만들고 최근접 거리를 패치 점수로, 검증셋 패치 평균으로 위치별 정규화, 이미지 점수는 상위 5개 패치 평균. 비교용으로 PaDiM(위치별 가우시안)과 Gaussian(대각 공분산)도 같은 인터페이스로 구현.
4. 기준선: 정상 검증 점수의 99퍼센타일, 기종·스텝마다. 검증셋 150장 미만이면 reliable=false.
5. 일치율: 100 x 0.5^(점수/기준선). 기준선에서 정확히 50, 판정과 항상 일관. (식은 임의로 정함)
- 패치 크기·이웃 반경·상위 개수·99퍼센타일은 초기값이며 튜닝 근거가 없어(불량 스텝당 1–3건) 건드리지 않았다.

### A5. 실험과 의사결정
#### A5.1 검증셋 크기
검증셋 8–12장일 때 99퍼센타일은 사실상 "최댓값 근처"라 FPR이 1119%로 나오는 등 무의미했다. 150장 이상 확보로 FPR 0.84%대로 안정화. -> 구현에 반영, 부족하면 reliable=false 표시.
#### A5.2 정렬 정책
강제(실패 시 제외)는 데이터 손실 최대 55%와 "정렬 실패 = 자동 FAIL" 부작용, 무정렬은 라벨 누락도 못 잡음 -> soft 채택. 합성 데이터에서 정렬을 끄면 AUROC 1.0->0.91, recall 1.0->0.0으로 재현.

#### A5.5 정렬은 병목이 아니었다 (테스트한 스텝 한정)
변환 모델 변경(원근), 해상도 2배, ORB 실패 시 ECC 재시도를 비교했다.

#### A5.6 009AA step 3의 불량 3개와 ROI 점수
라벨 영역을 잘라 비교한 결과(육안 판독, `[TODO]` 원본 해상도로 재확인): 2EX36613 = 제품명칭 라벨 없음, 2EX36524 = 끝의 "N" 누락("2206"), 2EX36661 = 기대 라벨은 2206N인데 사진에는 2006N이 있음(사람이 직접 확인, 라벨 숫자 불일치)("2006N").
라벨 영역(ROI)만 점수화하면 "라벨 없음"은 순위 100%(정상 최대 2.98 < 불량 3.26), 나머지 둘은 25–32%. 32px 패치의 엣지·색·텍스처 통계로는 글자 하나 차이를 구분하기 어렵다고 해석. ROI는 사진을 보고 정한 영역이라 낙관적이며 스텝마다 사람이 지정해야 해서 파이프라인에는 넣지 않고 진단 도구로만 사용.
#### A5.7 기준선을 낮추지 않은 이유
한 제품에 스텝이 15개 정도이므로 스텝당 오탐률 p면 제품 하나가 잘못 FAIL될 확률은 1-(1-p)^15: 1% -> 약 14%, 5% -> 약 54%, 10% -> 약 79%(스텝 독립 가정). 실제 불량은 0.28%뿐이라 1%여도 오탐 제품이 불량보다 약 50배 많다.

#### A5.9 정상이 적은 기종과 k-fold 모드
전 기종 학습에서 정상이 부족한 6개 기종(3029C005AA 9제품, 3029C006AA 5, 3029C010AA 20, 3030C002AA 2, 3030C004AA 17, 3031C001AA 5)의 91개 칸이 "train 10장 미만"으로 학습되지 않았고, 이 기종들은 추론이 불가능해졌다. 정상이 60장 미만인 칸은 train/val 분할 대신 k-fold로 바꿨다: 정상 전부로 최종 모델을 만들고, 기준선은 각 정상을 "그 이미지가 빠진 폴드로 학습한 모델"로 점수화한 out-of-fold 점수의 99퍼센타일로 정한다.
- 한계: 표본이 적어 기준선 신뢰도는 낮고(reliable=false로 표시), 독립된 test가 없어 오탐률을 따로 추정할 수 없으며, 최종 모델은 폴드 모델보다 뱅크가 커서 점수가 약간 낮게 나온다.
- 합성 데이터에서 동작은 확인했다(정상 8장으로 불량 6개 중 2개 검출). `[TODO]` 실데이터 결과(`run_update.bat`).
